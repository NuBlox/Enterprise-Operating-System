## Purpose

Provide a concise initiation-level description of why the NuBlox project exists, what it will deliver, who it is intended to serve and the boundaries within which detailed planning will proceed.

## Project name

**NuBlox Enterprise Operating System — Initial Product Definition and Delivery Project**

## Problem statement

The project is testing whether organisations with complex cross-functional and professional/project delivery work experience material cost, delay, risk and management friction because operating data, delivery work, commercial context, decisions and evidence are spread across disconnected systems and manual processes.

## Proposed response

Define and build a coherent enterprise operating environment that connects selected end-to-end business outcomes across organisational operations and the work through which the organisation creates value.

The project will not assume that every capability belongs natively in NuBlox. It will determine when NuBlox should perform, govern, coordinate or integrate with other systems based on requirements and customer value.

## Intended users

Initial user groups to validate include:

- professionals performing project/service work;
- project and team managers;
- commercial/finance roles;
- operational and functional managers;
- executives;
- governance/assurance roles;
- IT/system administrators;
- external collaborators where required by the workflow.

## Initial market hypothesis

UK mid-market multidisciplinary built-environment consultancies and project-services firms.

## Expected project outcomes

- validated customer/problem definition;
- prioritised end-to-end business scenarios;
- controlled functional/non-functional requirements;
- information, integration and reporting requirements;
- coherent product/UX design;
- production-grade solution architecture;
- secure implementation foundations;
- representative end-to-end working software;
- migration/onboarding approach;
- pilot evidence and measurable outcomes;
- production-launch recommendation.

## Delivery approach

The project will use staged evidence gates:

```text
Initiation
→ Requirements
→ Architecture & Design
→ Foundation implementation
→ End-to-end slices
→ Pilot
→ Production readiness
```

Work should be incremental, but each increment must remain traceable to the controlled requirements and programme objectives.

## Key assumptions

- a commercially meaningful customer problem exists;
- prospective customers will participate in discovery/pilots;
- NuBlox can deliver reusable product capability rather than bespoke implementations;
- secure cloud software is a plausible delivery model, subject to later decision;
- specialist systems will remain where they create more value than replacement.

All assumptions require validation.

## Key constraints

- no approved detailed budget yet;
- limited validated customer evidence;
- no final architecture/technology stack;
- no final feature or capability catalogue;
- compliance and operational expectations may vary by customer/jurisdiction;
- product scope must remain supportable by available delivery capacity.

## Immediate next work

1. Complete project initiation controls.
2. Conduct primary customer discovery.
3. Define business/end-to-end scenarios.
4. Establish business, functional and non-functional requirements.
5. Baseline data/integration/reporting/security requirements.
6. Design solution options and architecture.
7. Cost and authorise the first implementation slice.
